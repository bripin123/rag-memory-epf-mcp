# 종결 판정 — 그래프는 우리 corpus 에서 회수를 개선하지 못한다 (2026-08-22 세션44)

> 이 파일은 손으로 쓴 종결 기록이다. `DECISION.md` 는 `run-decision.mjs` 가 생성하므로 여기에 쓴다.
> 등급 = **`provisional`**. A·M holdout 이 없고(T9 미작성) `POWER.md` 는 동결되지 않았다(`DECISION.md` I-4).
> 이 회차는 **dev split** 이며 동결된 Stage-2 시험을 통과·탈락한 것이 아니라 **futility 로 닫는다**.

- Holm 가족 m=3 고정 (미측정 endpoint 는 p=1) → 첫 단 임계 **0.05/3 = 0.0167**
- `POWER.md`: candidate endpoint 요구 N = hub **80** / hal **61** / uap 134. uap 은 그 파일에 **이미 `inconclusive` 로 사전 선언**돼 있다
- 팔 A4 의 규칙(청크당 코사인 top-8, 8 = 현행 청크당 링크 중앙값)은 빌더 스크립트에 **실행 전** 박았다

## 3. 판정

**어느 팔도 MCID 0.05 에 닿지 못했다.** 최고값 A3 macro 0.044.

동결 규칙을 그대로 적용하면:
- hub A3: CI 하한 **-0.007 < 0** → I-1 첫 관문에서 탈락 (0 을 배제하지 못한다)
- hal A3: CI 하한 0.014 > 0 이나 sign p **0.031 > Holm 첫 단 0.0167** → 탈락
- → **0/2**. 2/3 다수결은 성립할 수 없다.

🔴 **검정력 실태 — 이 회차는 애초에 결론을 낼 수 있는 규모가 아니었다.**
candidate endpoint 는 A+M **n=60** 으로 돌았고 `POWER.md` 요구는 hub 80 · hal 61 이다. **두 corpus 다 미달**이다.
(세션 중 한때 "hub·hal 은 powered" 라고 적었는데 그 83/82/84 는 **K 질의 수**였다. 분모 착오. advisor r1 이 잡았고 `queries.*.jsonl` 재측정으로 확인했다.)

## 4. 종결 사유 = futility (동결 시험 탈락이 아니다)

수렴하는 독립 증거 셋 + 측정된 천장:

1. 그래프 **재랭킹**은 3/3 corpus 에서 해로웠다 (세션35~36 · sign test p < 7e-11) → v5.3.0 에서 기본 off
   ⚠ **[2026-08-23 추가] 이 측정의 전제가 그 뒤 사라졌다 — 인용할 때 같이 읽을 것.** 당시 해악 기전은
   *"링크가 많은 청크가 쿼리와 우연히 겹치는 entity 를 여럿 갖게 되어 cap 0.4 를 채운다"* 였고(실측 예 =
   `vector_similarity 0` 청크가 **링크 90개**로 top-3 진입), 그 링크의 97.8% 가 파일명 우연 일치였다.
   v6.0.0 게이트 + hub DB 청소 후 청크당 링크 수는 **중앙값 17→2 · p90 90→7 · 최대 172→39**,
   링크 있는 청크는 2,009→1,078(전체의 37%)이다. **즉 "재랭킹은 해롭다"는 현재 데이터에 대해 미측정이다.**
   🔴 그렇다고 «이롭다» 로 뒤집히는 것도 아니다 — 이득을 재려면 순위 지표가 필요한데 `suite/POWER.md`
   기준 필요 표본이 3,321~4,215 이고 우리는 84 다(검정력 ~0). **잴 수 있는 것은 «여전히 해로운가» 뿐**이고
   (해악은 크면 적은 표본으로도 방향이 잡힌다), 그 재측정 비용은 기존 하네스 + LLM 호출 0 + 수 분이다.
   **`useGraph` 기본 off 는 유지한다** — 보수적 기본값은 유지에 새 근거가 필요하지 않고, 바꾸려면 필요한
   근거를 지금 만들 수단이 없다. §4 의 천장 논증은 `recall@30` 기준이라 **재랭킹 축에는 적용되지 않는다**
   (재랭킹은 recall 을 바꾸지 않는다).
2. 그래프 **엣지 품질**: edge validity 0.077~0.194 vs 게이트 0.80. 문서 근거 추출로 도달 가능한 상한이 31~35%(세션43 전수)
3. 그래프 **후보 생성**: 세 팔 전부 dev 에서 sub-MCID (이 회차)
4. 🔴 **천장** — rrf2 recall@30(doc) 이 이미 **hub 0.89 · hal 0.92** 다. 남은 여지가 0.11 / 0.08 뿐이라 MCID 0.05 는 **남은 개선분의 45~62%** 를 요구한다. 즉 **완벽한 그래프 채널이라도 이 corpus 에서 얻을 수 있는 최대치가 0.08~0.11 이다.** 상금 자체가 작다.

**결론: 그래프 축에 더 투자하지 않는다. `useGraph` 는 영구히 기본 off 로 둔다.**
범위 한정 = ***우리 corpus 와 우리 질의 분포에서***. "그래프 RAG 는 안 된다"는 일반 명제로 쓰지 않는다.

## 5. 탐색적 관찰 (미등록 · 판정 근거 아님)

**[탐색적 · 사전 미등록]** alias 링크(전체의 91.6%) 제거는 두 corpus 어디서도 Δrecall 을 낮추지 않았고 macro 를 0.029 → 0.044 로 옮겼다.
**A3−A2 paired 대비 자체는 검정하지 않았다** — 희석 가설과 일관하나 유해성 입증은 아니다. hub 의 +0.025 는 CI 폭 ~0.1 안의 이동이고 비영 질의가 6~9개뿐이라 질의 한둘의 flip 수준이다.

alias 경로를 걷어낼 **독립 근거는 결과 지표가 아니라 기전 전수 측정**이다:
링크 65,935 중 91.6%(60,427)가 observations 의 파일명 토큰 매칭이고, 단일 alias `agents.md` 하나가 entity 81개 × 청크 440개로 전체의 약 54% 를 만든다. 이는 검색 효능과 무관한 **데이터 품질 결함**이다.

🔴 **이 관찰은 「청소하면 그래프가 도움이 된다」의 근거로 인용될 수 없다 — A3 도 동결 규칙을 통과하지 못했다.**

## 6. A4(임베딩 링크)에 대한 정직한 기술

chunk 임베딩과 entity 임베딩이 **같은 bge-m3** 다. 코사인 top-8 로 만든 링크는 vector 채널의 거친 사본이라 새 후보를 만들지 못한다 —
A4 ≈ 0 은 측정 전에 상당 부분 분석적으로 예측 가능했다. **"가설이 측정으로 기각됐다"보다 "같은 인코더로 만든 링크는 vector 와 중복임을 확인했다"가 정확하다.**
다른 인코더나 entity 서술 전용 임베딩은 **미시험**이다. 판정에는 비하중.

## 8. 방법론 한계 (기록해 둘 것)

- **gold 편향**: A·M 질의는 `documents.content` 기반으로 작성돼 문서 표면 근접성이 내장돼 있다. vector+FTS 에 유리하고 그래프의 이론적 강점(다중 홉·어휘 불일치)은 과소 대표된다. 이 분포가 실제 사용(부팅·known-item 회수)과 일치하므로 이 제품에 대한 외적 타당도는 성립한다.
- **arm 다중성**: 게이트 하나에 팔 셋을 댔다. fail 판정에는 무해하나, A3 가 넘었다면 다중비교 조정 없이 주장할 수 없었다.
- **미실행**: A·M holdout(T9), 사람 qrel, uap.
